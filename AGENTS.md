# Instructions For Agents

Use YAIML as SpriteWrite project memory, not as a replacement for task-specific instructions.

The maintainer treats these projects as works in progress: latest working files, including uncommitted edits, are the current baseline. Preserve that work; branch names and older commits do not establish production state or permission for Git mutations.

## YAIML Context And Skills

Read and follow [.yaiml/YAIML_GUIDE.md](.yaiml/YAIML_GUIDE.md) for ordinary work. Use root [yaiml.yml](yaiml.yml) to locate all four core roles. Read the audit receipt and pending records before relying on core snapshots, headers before bodies. Reuse current context; select relevant methods from host metadata or the [catalog](.yaiml/skills/INDEX.md), read their bodies and pass requested actions/counts/perspectives unchanged. Native `.agents/skills/` entries route to canonical methods.

Before finishing, maintain material understanding and revision/change records as the guide directs, including confirmed conversational decisions and new verification evidence. Respect read-only scope and no-op work. Preserve human direction, project-specific authority, privacy and unresolved conflicts. Keep routine edits passage-scoped; broad compression needs its own scope. Report word-budget growth and overages outside memory.

At startup/context refresh, consider coordination from available context. For a concrete benefit, read [.yaiml/YAIMLACP.md](.yaiml/YAIMLACP.md), explain scope, access, limits, cost and the single-agent alternative, and obtain affirmative confirmation before first use or changed scope/cost. Otherwise continue independently.

Init executes bootstrap immediately. Routine startup uses local guidance without upstream polling or backlog execution. “Update YAIML” means convention refresh; “prune SoT” or “compress project memory” means synthesis under the corresponding method. Neither grants Git publication permission.

See [.yaiml/MAINTAINER_GUIDE.md](.yaiml/MAINTAINER_GUIDE.md) for local maintenance. Read [docs/PRODUCT_VISION.md](docs/PRODUCT_VISION.md) for work touching product scope, UX hierarchy, AI assistance, recipes, templates, exports or engine-consumer positioning.
